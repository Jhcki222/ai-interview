# AI 기반 IT 면접 학습 플랫폼 구현 설계

작성일: 2026-11-04
상태: 사용자 승인 완료 — 구현 및 검증 진행

## 1. 목표와 범위

첨부한 전체 개발 명세서를 기준으로 실제 이용 가능한 한국어 웹 서비스를 만든다. 질문 학습, 회원 인증 및 개인 저장, 문서 기반 질문 생성, 대화형 AI 면접, 피드백, 배포 구성을 모두 포함한다. 구현 범위를 UI 데모로 축소하지 않는다.

현재 C:/interview-ai 작업 폴더에는 기존 애플리케이션이나 Git 저장소가 없다. 기존 구현을 보존해야 하는 충돌은 발견되지 않았다.

## 2. 검토한 디자인 소스

- 원본 키트: https://www.figma.com/design/ZKSQz4nsm1jbpJvOgSsKE4
- 전달된 노드 4098:3779는 Welcome 페이지다. 실제 Native Components 페이지 15:0에서 Menus and actions(6171:449), Navigation and search(6171:452), Selection and input(6171:458)의 디자인 컨텍스트 및 렌더 이미지를 확인했다.
- 두 번째 파일 https://www.figma.com/design/AmStZVrXJOT2OJr8y5R10Y 의 0:1은 도구가 반환한 구조상 자식 노드가 없는 빈 페이지다. 이 파일에 이미 완성된 제품 화면이 있다고 가정하지 않는다.
- 사용자 재전달 후 이 파일을 다시 조회하여 macOS Header, Alert, Group Box, Combo Box, Large/Small 다이얼로그 및 List Item을 확인했다. 업데이트된 구조를 데스크톱 웹 탐색과 공통 UI에 반영한다.
- 키트의 검색 필드, 버튼, 선택 컨트롤, 토글, 메뉴, 탭의 외형과 상호작용을 웹에 맞게 재사용한다. SwiftUI 코드나 운영체제 전용 기능을 웹에서 직접 실행할 수 있는 것으로 취급하지 않는다.
- 재사용한 각 컴포넌트의 원본 노드와 토큰 대응 관계를 문서화한다. 실제 사용 자산은 로컬 파일로 저장하며 임시 Figma 자산 URL을 런타임에서 사용하지 않는다.

## 3. 화면과 시각적 방향

반응형 웹을 기본으로 한다. iOS 전용 앱이나 SwiftUI 프로젝트는 만들지 않는다.

- 명세의 화이트/슬레이트 바탕, 인디고 포인트와 라이트/다크 테마를 CSS 변수로 정의한다.
- 키트에서 확인한 둥근 버튼과 검색창, 세그먼트 선택기, 얇은 경계선, 절제된 반투명 메뉴를 공통 UI에 적용한다.
- 반투명 효과는 탐색 메뉴와 오버레이 중심으로 사용하고 긴 답변 본문은 불투명 배경에 표시한다.
- 한국어를 읽기 쉬운 시스템 글꼴과 충분한 줄 간격을 사용한다. 터치 영역, 키보드 포커스, 접근성 이름을 제공한다.
- 데스크톱 질문 학습은 카테고리 사이드바와 질문 목록을 배치한다. 모바일에서는 카테고리를 Drawer로 연다.
- 홈은 작은 Hero, 질문 학습 및 AI 면접 진입부, 추천 질문과 카테고리로 구성한다. 사용자 데이터가 없을 때 임의의 학습 통계를 표시하지 않는다.
- 질문별 모범답안, 꼬리질문, 각 꼬리질문의 답안은 독립적으로 펼친다. 답변 편집과 학습 상태 변경을 같은 흐름에서 지원한다.
- AI 면접은 설정 → 문서 추출 → 분석 결과 확인/수정 → 질문 생성 → 질문 학습 또는 실전 대화 → 최종 피드백으로 이어진다.

## 4. 아키텍처와 구현 선택

권장 방식은 명세의 단일 Next.js 서버리스 애플리케이션이다. 별도 백엔드는 운영 복잡성을 늘리고, 프런트엔드만 구현하면 인증과 AI 기능이 완성되지 않으므로 선택하지 않는다.

- Next.js App Router, TypeScript, React, Tailwind CSS, shadcn/ui, Lucide React를 사용한다.
- 폼 검증은 React Hook Form과 Zod를 사용한다. 상태 라이브러리와 Motion은 실제 필요가 생기는 범위에서만 추가한다.
- 기본 질문은 정적 JSON으로 관리하고 Server Component에서 직접 읽는다.
- Supabase Auth 및 @supabase/ssr로 인증하고 PostgreSQL과 RLS로 회원 데이터를 저장한다.
- AI 호출은 Next.js Route Handler에서 Vercel AI SDK와 외부 LLM을 통해 수행한다. 모델명과 비밀 키는 서버 환경변수로 설정한다.
- PDF는 pdfjs-dist, DOCX는 mammoth, TXT는 기본 디코딩으로 텍스트를 추출한다. 파일 원본의 영구 저장은 기본적으로 수행하지 않는다.
- 배포 대상은 Vercel과 Supabase다. 추가 상시 서버, Redis, 컨테이너, 벡터 DB를 도입하지 않는다.

## 5. 기능과 데이터 경계

### 질문 학습

명세의 일곱 카테고리와 하위 주제를 지원한다. 질문마다 고유 ID, 난이도, 중요도, 핵심 키워드, 다섯 영역의 모범답안과 최소 두 개의 답안 포함 꼬리질문을 제공한다. 콘텐츠 목표는 명세의 분류별 총 380문항 이상이다. 반복 문구로 수량만 채우지 않고 기술 정확성을 검토한다. 검증 스크립트가 필드, 분류, 중복 ID와 답안 누락을 검사한다.

검색과 카테고리/난이도/중요도/학습 상태/북마크 필터를 지원한다. 비회원 답변과 임시 진행 상태는 sessionStorage에 저장한다. 영구 저장 시 로그인 안내를 표시하며 로그인 후 임시 데이터 가져오기는 사용자 동의를 받는다.

### 회원 데이터

profiles, saved_questions, user_answers, learning_progress 테이블을 SQL 마이그레이션으로 관리한다. 원본 질문과 개인 저장 질문의 안정적인 키를 구분한다. 개인 질문 저장 시 모범답안과 꼬리질문을 함께 복사하여 원본 변경으로 개인 콘텐츠가 달라지지 않게 한다.

서버에서 사용자 인증을 확인하고 RLS에서도 소유권을 검증한다. 개인 질문/답변 CRUD, 북마크, 메모, 학습 상태, 실제 데이터 기반 학습 현황을 구현한다. 외래키, 사용자별 UNIQUE 제약, 조회 인덱스를 포함한다.

회원가입, 로그인, 로그아웃, 이메일 확인, 비밀번호 재설정과 안전한 내부 경로 복귀를 제공한다. 브라우저 localStorage에 JWT를 수동 저장하지 않는다. 인증 쿠키는 Supabase SSR의 지원 패턴과 보안 옵션에 맞춘다.

### 문서와 AI 면접

PDF/DOCX/TXT를 최대 3개, 파일당 5MB로 제한하고 추출 후 문자 수 제한도 적용한다. 빈 문서, 지원하지 않는 형식, 파싱 실패를 구분해 안내한다. 분석 결과는 사용자가 수정할 수 있다. 원문에 없는 경력이나 수치를 사실로 생성하지 않도록 출처 근거와 추론을 구분한다.

질문 생성 및 학습 모드와 실전 대화 모드를 모두 지원한다. 질문은 5/10/15개로 설정하며 실전 모드에서는 한 번에 하나씩 제시한다. 질문마다 모범답안과 꼬리질문을 제공한다. 정확성, 논리성, 구체성, 질문 적합성, 실무 적용성을 근거와 함께 평가하며 AI 추정 평가임을 표시한다.

TypeScript 상태 머신으로 SETUP부터 COMPLETED까지 명세의 상태 전이를 관리한다. 새로고침 복원, 중복 제출 방지, 취소, 제한된 재시도, 타임아웃을 지원한다. SSE 수신 중인 불완전 JSON을 최종 결과로 저장하지 않고 완료 후 Zod 검증을 통과한 데이터만 반영한다. 원문은 sessionStorage에 불필요하게 보관하지 않는다.

## 6. 보안과 사용량 관리

- AI 키와 Supabase 서비스 역할 키는 서버 전용으로 취급한다.
- AI 사용량은 Supabase의 원자적 사용량 갱신 함수로 제한한다. 서버리스 메모리 카운터에 의존하지 않는다.
- 비회원 식별 쿠키와 신뢰 가능한 배포 요청 IP의 해시, 회원 ID를 이용해 요청 제한을 적용한다. 원본 IP의 불필요한 보관을 피한다.
- 요청 크기, 문서 길이, 생성 질문 수, 출력 토큰, 대화 길이에 상한을 둔다.
- 문서를 신뢰할 수 없는 데이터로 취급하고 문서 안의 지시를 시스템 지시로 실행하지 않는다.
- 변경 요청의 출처와 인증을 검증하며 원문/비밀 키가 로그나 클라이언트 번들에 노출되지 않게 한다.
- 외부 서비스가 미설정되면 해당 기능에 설정 필요 상태를 표시한다. 모의 AI 결과나 가짜 회원 저장 성공을 반환하지 않는다.

## 7. 라우팅과 산출물

명세의 /, /questions, /questions/[id], /interview, /interview/[id], /login, /signup, /my/questions, /my/answers, /my/bookmarks, /my/progress, /settings를 구현한다. 이메일 확인 및 비밀번호 복구에 필요한 보조 경로를 추가한다.

전체 소스, 정적 질문 JSON, 공통 UI, SQL 마이그레이션, 서버 AI 프롬프트/스키마, 콘텐츠 검증기, 테스트, .env.example, 실행/배포 README를 제공한다. 실제 배포에는 사용자의 Supabase 프로젝트 및 LLM 키, 배포 대상 연결이 필요하다. 해당 값이 없는 상태를 실서비스 검증 완료로 보고하지 않는다.

## 8. 구현 순서와 검증

1. 프로젝트 초기화와 디자인 토큰, 공통 UI, 홈, 반응형/다크 모드.
2. 정적 질문 콘텐츠, 검색/필터, 독립 토글, 답변 편집과 비회원 복원.
3. Supabase 마이그레이션, 인증, 개인 CRUD, 북마크, 학습 현황.
4. 문서 파싱, 분석 결과 수정, 서버 AI 연동, 질문 생성과 저장.
5. 면접 상태 머신, 대화, 평가, 꼬리질문, 스트리밍과 최종 평가.
6. 접근성/오류 상태 점검, 보안 검증, 프로덕션 빌드, 배포 문서.

각 단계는 실행 가능한 상태로 마무리하되 전체 범위가 완료될 때까지 이어서 구현한다. 데이터 스키마, 권한, 사용량 경합, 상태 전이, 잘못된 AI 결과를 의미 있는 자동 테스트로 검증한다. 브라우저에서는 명세의 비회원 학습, 회원 저장, AI 면접, AI 질문 저장, 세션 유지 흐름과 모바일 레이아웃을 확인한다. 실제 외부 연동 검증과 로컬 테스트 결과를 구분해서 기록한다.

## 9. 설계 검토 결과

스택과 라우팅은 원본 명세를 따른다. 디자인 키트는 웹 공통 컨트롤의 원본으로 사용하며 빈 Figma 파일의 화면을 임의로 존재한다고 주장하지 않는다. 초기 질문 콘텐츠 수량 목표, 실제 AI 사용, 데이터 격리, 비회원 정책, 운영에 필요한 외부 설정을 명시했다. 구현 전에 이 설계에 대한 사용자 검토를 받는다.
