# 최종 독립 검토 기록

검토일: 2026-11-04 (Asia/Seoul)

## 범위와 기준

승인된 `docs/superpowers/specs/2026-11-04-interview-platform-design.md`와 구현 계획을 기준으로 현재 작업 폴더의 소스를 검토했다. Git 저장소가 없으므로 특정 커밋/SHA를 검토한 기록이 아니다. 정적 질문 콘텐츠는 작성 중이므로 이번 검토에서 일시적인 문항 수 부족을 결함으로 기록하지 않았다. 콘텐츠 검증과 최종 전체 빌드는 별도 완료 검증에 포함해야 한다. `.env.local` 또는 비밀 값은 읽거나 이 기록에 출력하지 않았다.

검토한 흐름은 공통 탐색·로그아웃, 질문 필터와 개인 답변/진행 기록, 비회원 임시 저장과 동의 기반 가져오기, SSR 인증·내부 경로 복귀, 회원 CRUD·RLS·중복 저장, 문서 추출, 분석 검토, 생성 질문 학습/대화, 복원·꼬리질문·최종 평가, 요청 크기·타임아웃·공급자별 응답 검증과 영속 사용량 제한이다.

## 남은 중요 발견 사항

### P2 — 회원 데이터 조회 실패 후 임시 기록 가져오기가 기존 답변을 덮어쓸 수 있음

현재 검토 스냅샷의 `hooks/use-learning.ts:65`에서 첫 회원 상태 조회가 실패하면 오류만 표시하고 `finally`에서 로딩을 끝낸다(`:76`, `:80`). `loaded`는 조회 성공 여부를 검사하지 않는다(`:256`). 회원 데이터가 빈 객체인 상태에서 가져오기 후보를 계산하고(`:211`), 가져오기에서 일반 UPSERT 답변 API를 호출한다(`:223`). 따라서 기존 서버 답변이 없는 것처럼 판단해 덮어쓸 수 있다. 같은 초기 조회 대기 중에도 질문의 진행/북마크 변경 컨트롤을 사용할 수 있어, 비어 있는 로컬 기본값을 서버의 기존 상태 위에 저장할 수 있다.

재현: 회원 A에 질문 X의 답변과 완료 상태를 저장한다. 같은 탭의 비회원 임시 기록에도 X의 다른 답변을 남긴다. 로그인 후 최초 `/api/me/state` 응답만 실패시키고 이후 쓰기 API는 정상으로 둔다. 현재 UI는 조회 오류 후에도 가져오기를 제시할 수 있으며, 승인하면 기존 답변을 일반 UPSERT로 바꾼다. 초기 GET을 지연시킨 상태에서 북마크를 누르는 경우에도 기존 완료 상태가 `NOT_STARTED` 기본값으로 바뀔 수 있다.

권장 수정: 소유자와 연결된 회원 데이터의 **조회 성공 상태**를 별도로 관리한다. 성공 전/실패 후에는 가져오기와 기존 데이터에 의존하는 회원 변경을 막고 재시도 UI를 제공한다. 동시 탭 수정까지 보호하려면 가져오기는 일반 UPSERT 대신 DB의 `ON CONFLICT DO NOTHING`에 해당하는 삽입 전용 경로를 사용하고 이미 존재하는 서버 기록을 보존해야 한다. 부모 작업자에게 전달했으며 수정 후 이 항목의 상태를 갱신해야 한다.

## 검토 중 확인하고 해결한 항목

- 회원 화면은 로드한 데이터의 소유자 ID를 확인하고 로그아웃/계정 변경 즉시 다른 소유자의 기록을 숨긴다. 진행 중 요청도 소유자·요청 버전으로 구분하여 오래된 응답을 반영하지 않는다.
- 회원 질문에서 처음 답변·진행·북마크를 저장할 수 있다. 개인 질문 키는 원본 ID가 아니라 `saved:<DB UUID>`다.
- SQL은 저장 스냅샷의 필수 구조·답안·두 개 이상의 완전한 꼬리질문을 검증한다. 부모 참조 검사에 `FOR KEY SHARE`가 있어 삭제와 자식 삽입을 직렬화한다.
- 같은 회원/원본 ID 중복 저장은 생성 열 UNIQUE 제약으로 막고 API가 첫 개인 스냅샷을 그대로 반환한다. 생성 질문은 세션 접두사 ID로 서로 다른 면접의 모델 ID 충돌을 피한다.
- 설정된 프로젝트의 보호 경로 비회원 요청은 내부 원래 경로와 쿼리를 `next`로 보존해 로그인으로 이동하며 쿠키 변경도 리다이렉트에 전달한다. 회원가입도 `next`를 전달한다.
- 완전한 면접 기록을 그대로 보내 크기 상한을 넘던 종합 평가는 모든 턴과 평가 영역을 유지하는 크기 측정된 발췌 요청을 사용한다. 전체 원본 기록은 화면/탭 세션에 유지된다.
- AI 질문 스키마가 회원 저장 스키마를 확장하므로 생성 성공 후 필드 길이 차이로 저장할 수 없던 계약 불일치를 해결했다.
- 비회원 상태만 있는 기록도 동의 기반 가져오기 후보에 포함한다.
- 문서 추출 시작 전에 취소 컨트롤러와 제한 시간을 만들고, 취소 시 PDF 작업을 종료하며 추출 뒤에도 신호를 검사한다. 취소 후 늦게 도착한 텍스트를 AI로 보내지 않는 회귀 테스트가 있다.
- Groq는 실제 구조화 출력을 위한 비스트리밍 `generateText`, OpenAI는 구조화 `streamText`를 사용한다. Groq 대기 중에는 처리 상태만 보내며 토큰 미리보기를 꾸미지 않는다. 완성 이벤트만 전체 스키마 검증 후 반영한다.
- 꼬리질문/현재 인덱스/답안/평가의 탭 복원, 최근 대화의 제한된 맥락, 최종 평가의 꼬리질문 기록 포함, 잘린 SSE/잘못된 완료 응답 거부를 확인했다.
- AI 사용량은 서비스 역할 전용 원자적 PostgreSQL 함수로 영속화하며 서명된 비회원 식별자와 Vercel에서 덮어쓰는 신뢰 헤더의 IP 해시를 함께 사용한다. DB 제한 서비스가 없으면 AI는 실패 상태를 반환한다.

## 실행한 검증과 경계

- `npx vitest run --exclude tests/questions.test.ts`: 17개 테스트 파일, 52개 테스트 통과(2026-11-04 10:20 KST 실행).
- `npx tsc --noEmit`: 같은 검증 실행에서 타입 오류 없음.
- 테스트 임시 경로는 sandbox 기본 임시 디렉터리의 rename 제한을 피하기 위해 작업 폴더 `.tmp`를 사용했다.
- `tests/auth-database.sql`은 직접 인증 쓰기의 JSON 무결성, 두 계정 RLS 격리, 다른 소유자 참조 거부, 중복 스냅샷 보존 및 삭제 정리를 검사하는 실제 DB 스크립트다. 이 검토 환경에는 PostgreSQL 연결/psql이 없어 실행하지 않았다. SQL 소스 검토나 로컬 단위 테스트를 실제 DB 격리·경합 검증으로 간주하지 않는다.
- 실제 Supabase 이메일 확인·복구·SSR 세션 갱신·RLS 및 RPC 병렬 경합, 배포 게이트웨이 IP 처리와 전체 배포 흐름은 외부 연결 검증 대상이다. 공급자만 별도로 확인한 결과가 있더라도 전체 `/api/ai`의 DB 사용량 제한까지 검증한 것으로 확대하지 않는다.
- 최종 콘텐츠 완성 뒤 전체 테스트·콘텐츠 검사·프로덕션 빌드와 데스크톱/모바일 브라우저 검증을 다시 기록해야 한다.
