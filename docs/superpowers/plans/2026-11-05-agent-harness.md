# 면접 실행 하네스 구현 계획

1. `lib/ai/harness/tools.ts`: 분석·생성·평가·꼬리질문·종합평가의 출력 계약과 실행 정책을 단일 목록으로 정의. 출력의 질문 수·중복 ID·평가 영역 검증 통합.
2. `lib/ai/harness/runtime.ts`: 입력 검증 → 제한된 제공자 실행 → 출력 검증 → 완료 또는 오류. 기존 reliability의 취소·재시도·동의 기반 fallback을 재사용. 기록에는 사용자 문서·답변·키를 넣지 않음.
3. `app/api/ai/route.ts`: 실제 AI 작업을 공통 런타임으로 연결, SSE로 실행 기록 전달. 사용량 차감은 기존 위치에서 논리 요청당1회.
4. `lib/ai/client.ts`, 면접 화면: 검증한 실행 기록을 한 요청 단위로 표시. 새 요청·재시도 시 초기화, 최대 기록 수 제한.
5. 회귀 테스트: 잘못된 입력 시 호출 금지, 잘못된 출력 시 완료 금지, 동의 없는 fallback 금지, 취소 시 호출 금지, 기록의 민감정보 제외. 실제 합성 평가 요청과 프로덕션 빌드 검증.

별도 DB·서버 추가는 범위 밖. 체크포인트는 기존 브라우저 세션이며 서버 영속 워크플로와 정확히 한번 실행을 보장하지 않음.
