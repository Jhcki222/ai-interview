# 지원 산업·직무 카탈로그

확인일: **2026-11-04**. 구현: `lib/interview/job-catalog.ts`. 이 모듈은 서버·인증·파일 시스템 의존 없이 브라우저에서 가져올 수 있는 상수 데이터만 내보낸다.

## 범위와 구분

`INDUSTRIES`는 **지원 기업의 산업·사업 맥락** 21개다. 일반 IT, 은행, 공기업·공공기관, 보험, 증권, 핀테크, 제조, 모빌리티, 커머스, 통신, 미디어, 의료, 게임, 교육, 에너지, 물류, 건설, 여행, 농식품, IT 서비스, 보안을 포함한다. 업종은 일하는 환경이며 백엔드·AI·DevOps 같은 직무가 아니다. 공공기관은 소유·기관 성격도 포함하는 실용적 지원 맥락이므로 이 목록을 한국표준산업분류의 공식 코드표로 부르지 않는다.

`JOB_GROUPS`는 **수행 업무**를 기준으로 묶은 직무 72개다.

| 그룹 ID | 표시 그룹 | 직무 수 |
| --- | --- | ---: |
| `software` | 소프트웨어·서비스 개발 | 16 |
| `ai-data` | AI·머신러닝·데이터 | 12 |
| `infrastructure-operations` | 인프라·클라우드·운영 | 12 |
| `security` | 보안·개인정보·컴플라이언스 | 8 |
| `quality` | QA·테스트·소프트웨어 품질 | 6 |
| `technology-product` | 기술 기획·설계·프로젝트 | 6 |
| `banking-it` | 은행·금융 도메인 IT | 6 |
| `public-it` | 공기업·공공기관 전산 | 6 |

은행·공공 산업을 골라도 백엔드·AI·인프라 같은 공통 직무를 선택할 수 있어야 한다. 은행 계정계·정보계·디지털 채널과 공공 전산·전자정부 등은 도메인 특화 업무를 더 구체적으로 표현하기 위한 별도 그룹이다. 같은 개발 역량을 일부 공유할 수 있으나 단순한 한글·영문 별칭만 나누어 수량을 늘리지 않았다. 회사별 업무 경계는 다르므로 공고와 사용자 설명을 함께 확인해야 한다.

하드웨어 설계·순수 통신 시공·비IT 일반 직무 전체까지 포괄하는 사전은 아니다. IT 면접을 위한 폭넓은 초기 선택지이며 전 세계 모든 직업이나 모든 기관의 채용 명칭을 완전히 포함한다고 주장하지 않는다.

## 공식 자료에서 확인한 분류 근거

1. **NCS 정보통신·정보기술 분류**: 정보기술전략·계획, 정보기술개발의 SW아키텍처·응용SW엔지니어링, 정보기술운영의 IT시스템관리·IT기술지원 등 분리를 확인했다. 개발·운영·설계·기술 기획을 다른 업무 그룹으로 나눈 근거다. [NCS 공정채용 직무·능력단위 분류](https://ncs.go.kr/blind/bl04/RegedJdspt.do?entsrNo=101-82-10054)

2. **한국고용정보원/워크넷 공식 경력가이드**: `한국고용직업분류 2025` 표에서 소프트웨어 개발자, 네트워크 시스템 개발자 및 정보보안 전문가, 데이터 전문가, 정보시스템 및 웹 운영자를 구분한다. 관련 직업에 시스템·응용 소프트웨어 개발자, 인공지능연구원, 데이터분석가, DB 관리자, 네트워크관리자 등을 확인했다. 이는 큰 직업군의 근거이며, 아래의 현대 채용 명칭 하나하나에 공식 KECO 코드를 부여했다는 뜻은 아니다. [한국고용정보원 「대학 전공별 경력가이드 안내 자료」, PDF 인쇄쪽 28–30](https://www.work.go.kr/framework/filedownload/keisDownload.do?filePathName=oHBzib3Tsgxld0j94wJVE8nwpmxv7UvLLE4wk5KpcRL8uZROQS%2BlUOuohCvY5P0U53CBvLLm4Psh7KvX9L%2B%2F9g%3D%3D&realFileNm=64yA7ZWZIOyghOqzteuzhCDqsr3roKUg6rCA7J2065OcIOyViOuCtOyekOujjC5wZGY%3D)

3. **은행의 직접 직무 설명**: IBK기업은행 공식 인터뷰는 IT 업무가 은행 시스템의 개발·기획·관리·운영을 포함하고, 계정계 DB 및 대면·비대면 채널 미들웨어 같은 업무를 설명한다. 따라서 “은행” 산업과 “은행 IT 개발·운영”, 계정계·정보계·채널 등의 업무를 구분했다. 해당 게시물은 2023년 설명이므로 현행 조직·모집 인원·현재 채용 중이라는 주장의 근거로 사용하지 않았다. [IBK기업은행 공식 IT시스템운영 직무 인터뷰](https://blog.ibk.co.kr/2882)

4. **공기업의 직접 NCS 직무 설명**: 인천국제공항공사는 IT시스템관리 아래 응용SW·네트워크·DB·보안 운영과 모니터링·예방·장애 조치를 설명한다. 공공 IT를 막연한 행정 직무가 아닌 개발·운영·데이터·사업관리로 구체화하는 근거로 참고했다. 한 기관의 직무가 모든 공기업의 직무와 같다는 의미는 아니다. [인천국제공항공사 NCS 직무 설명](https://www.airport.kr/co_ko/839/subview.do)

NCS는 능력단위 중심의 직무 표준, KECO는 직업 분류다. 둘을 동일한 분류로 취급하지 않았다. DevOps·SRE·MLOps·LLM·SDET 등의 국제 용어와 세부 산업별 역할은 공식 분류의 방향을 참고한 **제품 편집상의 선택 명칭**이다. 이 카탈로그의 영어 표현도 법정 직업명이나 기관 공인 번역이 아니다.

## 구현·호환 규칙

- `INDUSTRIES: { id: string; label: string }[]`와 `JOB_GROUPS: { id: string; label: string; roles: string[] }[]`를 내보낸다. 산업과 그룹 ID는 표시 이름과 분리된 고정 식별자다.
- 기존 기본값과 세션의 **`백엔드 개발자`** 문자열을 그대로 유지했다. 나머지는 검색·이해를 돕도록 한국어와 국제 용어를 함께 표시했다.
- 이 목록은 선택 편의를 위한 카탈로그다. 기존 저장값·세션에 목록에 없는 직무명이 있다는 이유로 유효한 기록을 버리지 않는다. 새 필드를 추가한 UI도 복원 시 기존 직무 문자열을 보존해야 한다.
- 산업 선택으로 직무를 강제 제한하지 않는다. 은행의 AI 엔지니어, 공기업의 DevOps 등 여러 조합이 가능하다.

## 검증 기록

테스트를 먼저 작성하고 빈 상수에서 산업·직무 수량 조건이 실패하는 것을 관측한 뒤 데이터를 채웠다. `tests/interview-job-catalog.test.ts` **3개 테스트 통과**: 산업 ID·이름 중복, 60–80개 직무 범위, 직무 이름 중복, 필수 AI·백엔드·서비스 개발·인프라·DevOps·은행 IT·공공 전산 포함, 빈 그룹·빈 이름 및 직렬화 가능한 데이터 구조를 검증한다.
